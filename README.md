# 視唱チェッカー（sing2check）

マイクで歌を拾い、譜面どおりの音程で歌えたかを音ごとに判定する Web アプリ。課題は「ソルフェージュ練習帳」と同じコア（`src/core/solfege-core.js`）で作る。静的サイト、バックエンドなし、記録は端末の localStorage のみ。

仕様は `../handoff/sing2check-handoff.md`（以下「ハンドオフ文書」）。この README は、動かし方と、実装で決めたこと・確かめたことだけを書く。

## 動かす

```sh
npm install
npm run dev          # http://localhost:5173/ （localhost ならマイクが使える）
npm test             # Vitest（約 2 分半。ほとんどが通し試験）
npm run test:full    # 通し試験の全量（各レベル 30 課題。約 13 分）
npm run typecheck
npm run build        # dist/ に出力
npm run e2e          # ビルドしたものを Chrome で通す（先に npm run build）
```

Node 22.18 以降（`tools/*.ts` と `e2e/run.mjs` が TypeScript をそのまま実行するため）。

### iPhone 実機で試す

`getUserMedia` は HTTPS（または localhost）でしか使えない。

```sh
npm run dev:host     # 自己署名の HTTPS で、LAN に公開する（HTTPS=1 vite --host）
```

iPhone の Safari で `https://<PC の LAN の IP>:5173/` を開き、証明書の警告を承認して進む。警告を承認したページでマイクが使えなければ、`mkcert` でローカル CA と証明書を作り、`vite.config.ts` の `server.https` に指定する（ハンドオフ文書 §3.4 の方法 B）。PC 側のファイアウォールで 5173 番を通す。

### 配置

公開先: <https://tetsuo925.github.io/sing2check/>。`main` に push すると `.github/workflows/deploy.yml` がビルドして GitHub Pages に配置する。

`vite.config.ts` の `base` は相対（`"./"`）にしてある。`dist/` の中身を、GitHub Pages のプロジェクトページにもユーザーサイト直下にも、設定を変えずに置ける。HTTPS で配信すること。

### コアを更新する

`src/core/solfege-core.js` は手で編集しない。練習帳のコアが変わったら書き出し直す。

```sh
node tools/extract-core.mjs <練習帳の index.html> src/core/solfege-core.js           # 書き出す
node tools/extract-core.mjs <練習帳の index.html> src/core/solfege-core.js --check   # 一致の確認
```

## 構成

```
src/
  core/      solfege-core.js（複写）、exercise.ts（課題番号・テンポ・カウントの拍数）
  audio/     config.ts・dsp.ts・loopback.ts（参照実装のまま）、capture.worklet.ts、engine.ts、
             runTake.ts（テイクとループバック試験の進行）、messages.ts、session.ts
  judge/     judge.ts（参照実装のまま）、take.ts（時刻・時間軸の補正）、stats.ts（集計・コピー文・レベルの提案）
  ui/        Score.tsx / scoreRender.ts（abcjs）、PitchChart.tsx、BeatDisplay.tsx、sheets/ ほか
  storage.ts localStorage
test/        Vitest。helpers/ に合成の歌い手（synth.ts）
e2e/run.mjs  Chrome の E2E（偽のマイク入力に合成の WAV）
tools/       extract-core.mjs、make-wav.ts、make-icons.mjs
```

しきい値はすべて `src/audio/config.ts` の `DEFAULT_CONFIG`（「実際の歌声で調整する初期値」）。

## 実装で決めたこと・ハンドオフ文書から変えたこと

| 項目 | 内容 | 理由 |
|---|---|---|
| 判定の表示（§11.1） | 各音の下は「階名 / `◯ −8`」の 2 行。**その幅で段が五線の 1.1 倍を超えるときは「階名 / `◯` / `−8`」の 3 行**に切り替える。それでも長い段があれば全段をその幅にそろえ、全体を縮めて収める | abcjs は歌詞の幅に合わせて音符を広げ、入りきらない段は五線より長くなる（表示は全体が縮む）。360px 幅で測ると、2 行のままでは 2/4 の 1 段 7 音で 0.67 倍、4/4 の 1 段 11 音で 0.45 倍に縮んだ。3 行にすると同じ課題で等倍と 0.75 倍。スマートフォンの幅ではほとんどの課題が 3 行になる |
| 歌詞の語 | 語の前後に `~`（改行しない空白）を足した。歌えていない音の 3 行目は空白だけの語 | 足さないと隣の語とくっつく。ABC の `*` は、abcjs 6.7.2 では休符の直後で 1 音ずれた（`test/score.test.ts` が検出） |
| 間引き率（§9.1） | `round(サンプルレート / 24000)`。48k・44.1k は設計どおり 1/2、96k・88.2k は 1/4、32k 以下は間引かない。再生用 PCM も同じ率 | 開発機の出力が 96kHz だった。1/2 のままだとフレームが 21ms になり低い声を取れない |
| ワークレットの時刻（§8.1） | フレームの時刻は、受けたサンプル数を自前で数えて出す。`currentFrame` がちょうど 1 ブロック小さいときは連続として扱う | Chrome で `currentFrame` が 1 ブロック古い値のまま読めることがあり（サンプルは連続）、途切れと誤検出して解析器を作り直していた |
| 途切れの表示 | カウントより後に途切れ（`gap`）があったら、結果に「録音が n 回途切れました」と出す | 文書には無い。実機確認の「gap が出ない」を画面で分かるようにした |
| クリックの遅れの推定（§7.3） | 往復の遅れを測ってあるときは、前後どちらへのずれも見る（探索を 200ms 手前から始める） | 参照実装の推定は 0 未満にならないので、測ったときより遅れが小さくなった場合を見つけられない |
| テンポの範囲（§5.2） | 既定の 0.6〜1.2 倍の**内側**の 4 の倍数（63 → 40〜72）。「−」「＋」は隣の 4 の倍数へ | 上限が 1.2 倍を超えないように |
| `tempoByLevel` のキー（§14.1） | 単純拍子は `"7"`、6/8 は `"7:6/8"` | Lv7 は 3/4（既定 72）と 6/8（既定 56）が混ざる。同じキーだと片方の値がもう片方の範囲の外になる |
| ヒントの記録 | 「主和音」「最初の音」を使った記録は、同じ課題の間は残る（「同じ課題でもう一度」でも true のまま） | 一度聞いた音は次のテイクにも効くため |
| マイクから何も届かなかったテイク | 記録せず、準備に戻して説明を出す | 全音「歌えていない」の記録が集計を汚すため |
| 画面 | ヘッダーに「マイク」（マイクの確認）を足した。録音中はレベルとテンポの行を隠し、拍の表示を下のボタンのすぐ上に固定。歌っている段が見える所まで自動で送る。結果では合否を譜面の上に置いた。入力のゲートはマイクの確認シートでも変えられる | 小さい画面で、拍の表示・歌っている段・合否が隠れないように |
| マイクを開いた直後のテイク | 鳴らし始めを 0.4 秒遅らせる（`MIC_SETTLE_SEC`） | iOS はマイクを開いた直後に出力の経路が切り替わり、最初の音が欠けやすい（実機では未確認。不要なら 0 にする） |
| 録音が成り立たなかったテイク | 届いた音がすべて無音（−90dBFS 以下）、またはフレームが終わりの 0.5 秒以上手前で止まっていたら、記録せず準備に戻して説明を出す | 通話などの割り込みでは、マイクは開いたまま無音になる・AudioContext が止まる。それを全音「歌えていない」として記録すると、レベルを下げる提案に効いてしまう |
| 音程の名前（§14.3） | `上行 4度`（数字と「度」の間は空けない） | 文書の中で例が 2 通りあった。名前の表（`上行 4度`、`下行 短3度`）に合わせた |

## 確かめたこと・確かめていないこと

Vitest（176 件）:

- `core.test.ts` 63 件、`dsp.test.ts` 25 件、`judge.test.ts` 17 件、`loopback.test.ts` 5 件（参照実装のテストの移植）
- `pipeline.test.ts` 20 件（通し試験。全量では §18 に書かれた 2 課題 `Lv7-70003`・`Lv8-80007` だけが失敗する。それ以外が失敗したら落ちる）
- `take.test.ts` 18 件（テイクの時刻、時間軸の補正、クリックの遅れ、96kHz）
- `stats.test.ts` 17 件（コピー文 8 行、音程の名前、レベルの提案）
- `score.test.ts` 11 件（abcjs 6.7.2 は jsdom で描ける。Lv1〜8 × 30 課題で、たどった符頭の数 = 音の数）

デスクトップ Chrome（ヘッドレス、偽のマイク入力に合成の歌）:

- `npm run e2e`: 正確に歌う → 合格／1 音を 2 半音上 → その音だけ ✕／1 音歌わない → その音だけ ー。記録・コピー文・再読み込み後の記録シートまで
- ワークレットの読み込み（`?worker&url`）は dev と build の両方で動く
- マイク拒否時の説明、バックグラウンド移行でテイクを捨ててマイクを閉じる、360〜430px で横スクロールなし、ライト / ダーク

WebKit（Playwright の WebKit、iPhone 13 相当の画面。iPhone の Safari そのものではない）:

- 起動、譜面と書体、ライト / ダーク、「主和音」「最初の音」の再生と停止、3 つのシートの開閉、コピー、マイク拒否時の説明
- マイクを許可して「歌う」→ ワークレットが読み込まれ、結果画面まで進む（偽のマイクは一定の音なので判定は不合格）。コンソールのエラーなし

読んで直しただけで、動かして確かめていない経路: 割り込みで無音・途中で止まった録音を記録しない、マイクを開いている途中に閉じたときの扱い、Wake Lock の取り直し、ループバック試験の中断。

**確かめていない**（実機でしか分からない）: iPhone の Safari での動作すべて（ハンドオフ文書 §16）、実際の声での判定、スピーカーを使うループバック試験の実測、デスクトップの Safari・Firefox。下のチェックリストで確かめる。

## 実機確認のチェックリスト（ハンドオフ文書 §20）

iPhone（iOS 17 以降）で確かめ、結果（OK / NG / メモ）を書き込む。デスクトップ Chrome / Safari でも一度ずつ。

**M1**
- [ ] 消音スイッチ ON でも「主和音」が鳴る
- [ ] 音量ボタンで音量が変わる
- [ ] 360〜430px 幅で崩れない・横スクロールなし・ダーク表示で譜が読める

**M2**
- [ ] 「マイクを使う」で許可ダイアログが出る。拒否 → 説明が出る → 設定で許可 → 再読み込みで使える
- [ ] 「マイク」シートの `エコー除去・サンプルレート・チャンネル数` の値をメモ
- [ ] レベルメーターが声に反応する（チャンネル 0 に音が入る）
- [ ] チューナーとチューナーアプリの差が ±10 セント以内（A3・A4・E4 くらいで）
- [ ] 実効サンプルレートの点検: 1 分間マイクを開いたまま、✕ が出ない
- [ ] ループバック試験（本体スピーカー）: 検出 440Hz ±5 セント以内、遅れの値をメモ、4 回のばらつき 10ms 以内
- [ ] 有線イヤホン・Bluetooth イヤホンでループバック試験が「測れませんでした」になる
- [ ] マイクを開いたあと「主和音」の音量が下がらないか（下がるなら `audio/engine.ts` の `setAudioSession` の順序を見直す。§16.1）
- [ ] 再生音にパチパチ音が出ないか
- [ ] ワークレットの処理が間に合う（結果に「録音が途切れました」が出ない、音切れしない）

**M3**
- [ ] Lv1・Lv4・Lv6 で正しく歌って合格（各 3 回）

- [ ] 「自分の歌を聴く」が鳴る
- [ ] good / ok のしきい値（25 / 50 セント）が自分の耳の感覚と合うか。合わなければ `audio/config.ts` の値を調整してメモ
